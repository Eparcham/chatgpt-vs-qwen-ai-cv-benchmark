# Evaluation methodology

This repository contains two distinct experiments.

## Phase 1 — shared 30-task benchmark

Both systems answered the same 30 AI/CV programming challenges. The historical published scores are retained unchanged:

- GPT-5.6 Sol: **96.2%**
- Qwen 3.8 120B: **79.9%**

The Phase-1 scoring dimensions were:

| Dimension | Weight |
|---|---:|
| Functional correctness | 50 |
| Robustness / edge cases | 15 |
| API / specification compliance | 10 |
| Algorithmic flow / design | 10 |
| Generated-code runtime efficiency | 5 |
| Code clarity / maintainability | 10 |

The original challenge-level archive is preserved in `phase1_task_scores.csv`.

## Phase 2 — cross-authored evaluation

Two independent 15-task sets were created:

- ChatGPT-authored public questions were answered by Qwen.
- Qwen-authored public questions were answered blindly by GPT-5.6 Sol.

The answering model was not given `reference_answer` or `grader_tests`.

The same six-part 100-point rubric is used for each solution. In
`cross_eval_task_scores.csv`, the dimension columns contain **points out of their
published weight**; `overall_score` is the sum of those six point values.

Cross-eval averages:

- GPT-5.6 Sol on Qwen-authored tasks: **96.4/100**
- Qwen 3.8 120B on ChatGPT-authored tasks: **90.9/100**

## Evidence policy

Scores are based on three types of evidence:

1. Executable checks where the specification permits deterministic validation.
2. Comparison against a reference implementation when that reference survives a separate technical audit.
3. Specification-first code review for API behavior, edge cases, algorithm design and maintainability.

A reference implementation is **not** treated as infallible ground truth. If the prompt,
public example, grader description and reference disagree, the written task specification
takes priority and the conflict is recorded in `benchmark_quality_audit.csv`.

## Important comparability limitation

Phase 1 and Phase 2 are intentionally not pooled into a single universal model score.

- Phase 1 ChatGPT artifact is labeled **GPT-5.6 Sol**.
- Phase 2 blind ChatGPT responses were generated by **GPT-5.6 Sol**.
- Phase 2 models answered different, opponent-authored task sets.
- Qwen was served on private/self-hosted infrastructure; ChatGPT was served in the ChatGPT product.

Therefore this repository reports separate phase results and does not convert them into a
single claim of universal model accuracy.

## Output-length and token comparison

Provider-reported token usage was not logged comparably in the original runs. The repository therefore reports exact stored characters, whitespace-separated units, Python lexical tokens in generated code, and code lines. Where an LLM-token estimate is useful for relative output-length comparison, it uses the transparent common proxy `ceil(characters / 4)` and labels it as an estimate rather than actual token accounting.

## Descriptive bootstrap intervals

Bootstrap intervals in `statistical_summary.json` resample the benchmark tasks themselves. They describe sensitivity to this task sample and must not be interpreted as population-level confidence intervals for general model capability.


## Phase-1 rubric metadata note

An older draft of the benchmark JSON contained a four-dimension 70/15/10/5 recommended rubric. That draft rubric was not used for the published scores. The public benchmark JSON now retains it only as legacy provenance and separately records the six-dimension published rubric shown above.
